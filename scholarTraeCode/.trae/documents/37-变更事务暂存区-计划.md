# ㊝ 变更事务暂存区 — 实施计划

> P4 第 ㊝ 项。路线图 22/22、P3 六项、P4 ㉙㉛㉚㉜㊜ 已交付；
> ㊝ 是 1a/1b/1c 多次显式预留（「变更事务暂存区（㊝），本期不做」）的直接后继。
> 核心转变：**AI 的结构化文件改动从「直接落盘」变为「先进工作区暂存区，用户审阅 diff 后逐文件/批量接受才落盘」**——
> auto 模式下「AI 写完即生效、用户事后才发现」的最后一道失控口被堵上。

## 一、现状与缺口

1. **写链路直通磁盘**：scheduler 工具循环（L1208-1212）权限闸一过，`callMcpTool` → 内置 write/edit（builtinTools.ts 直接 fs.writeFile）或 MCP write_file/edit_file，立即生效。
2. **①权限闸是「事前单次放行」**：ask 模式逐条弹窗、auto 模式直接放行；回答的是「允不允许这一次调用」，回答不了「这个任务累积改了哪些文件、我能不能事后整体/部分接受」。
3. **②Git checkpoint 是「事后回滚」**：改错了靠 reset 整盘回退，做不到「任务完成后、生效前」逐文件挑拣。
4. **㊜任务快照只管任务态**：createdFiles 是名单不含内容；暂停/恢复/崩溃后没有「未生效变更」的存身之处。
5. **视图一致性风险**（本项最大设计点）：若 write 只进暂存不落盘，AI 随后 read/edit/grep/glob 会读到磁盘旧内容，Agent 在陈旧视图上工作——必须提供「暂存覆盖读」虚拟视图。
6. **bash 的磁盘依赖**：npm install/build 等命令对真实磁盘操作；暂存中的文件不存在，命令必失败——需要明确的门控语义，不能让模型盲撞。

## 二、目标

1. **暂存区**：审阅模式开启时，结构化变更工具（内置 write/edit/delete/move/copy + MCP write_file/create_file/edit_file/str_replace/delete_file/move_file/rename 等）的改动写入工作区级暂存区，不碰磁盘；同一文件的多次操作按「操作代数」合并为最终一条。
2. **虚拟视图**：AI 的 read/edit/grep/glob 自动基于「磁盘 + 暂存覆盖」，Agent 世界自洽——新建文件读得到、删除文件显不存在、edit 基于暂存后内容。
3. **审阅 UI**：任务进行中与结束后均可打开暂存面板，逐文件看 diff（复用 Monaco DiffEditor），支持接受/拒绝单个、全部接受/全部拒绝；任务完成且有未决变更时显著提示。
4. **bash 接受门**：审阅模式下暂存区非空时 AI 请求 bash/run_terminal_command，推「执行命令需先接受 N 个暂存变更」批量确认浮层——用户接受（全部落盘并清空暂存）后命令才执行，拒绝则回填原因让 Agent 等待/改道。保证模型面对的磁盘与其认知一致。
5. **持久化与生命周期闭环**：暂存区落 `.trae/staging/pending.json`，崩溃/重启后仍在；与㊜联动——暂停快照携带暂存、恢复后续用；放弃任务走既有 checkpoint 回滚（已接受落盘部分）+ 清空暂存；全部接受/拒绝后清空。
6. **冲突保护**：接受时若该文件磁盘内容与暂存基线不一致（用户/其他程序改过），阻断并提示，不覆盖他人改动。
7. **开关与默认**：工作区级「变更审阅」开关（独立于 readonly/ask/auto，持久化），本期**默认关**，设置页通用 Tab + ChatPanel 头部可切；开启时文件类变更不再走①的逐条 ask（不落盘即安全；bashGate 硬规则/边界/敏感文件照拦），bash 仍受①约束。

## 三、纯函数设计（核心零 IO 层）

**新增 `src/main/ai/changeStage.ts`（零 IO/Electron，规则一处）**

### 1. 类型
```ts
/** 暂存操作种类（用户视角的最终差异类型） */
type StageOpKind = 'create' | 'modify' | 'delete' | 'move'
/** 一条暂存记录：path 为目标路径；base* 为首次触碰时的磁盘基线（供 diff/冲突检测） */
interface StagedChange {
  path: string
  kind: StageOpKind
  /** create/move/modify 的最终内容（delete 无） */
  content: string | null
  /** move 来源路径（其效果并入：源文件删除 + 目标创建） */
  oldPath: string | null
  baseContent: string | null   // 首次暂存时的磁盘内容，新文件为 null
  baseExists: boolean
  baseHash: string             // baseContent 的简单哈希（冲突检测）
  updatedAt: number
}
/** 暂存区：path → 记录 */
type StageState = Map<string, StagedChange>
```

### 2. 操作代数（同一文件多次操作的合并规则，数据表驱动）
以「已有记录 kind + 新操作」二维合并，示例：
- 无 + write/create → `create`（base 取当时磁盘：存在则 create 升级为 modify）
- create + write/edit → 仍 `create`，内容覆盖/基于暂存内容改
- modify + write/edit → 仍 `modify`
- modify/create + delete → `delete`（create + delete → 记录直接消失，回到原状）
- delete + write → `modify`（删了又建，基线是最初磁盘内容）
- move：源路径记删除语义、目标记 create/modify；move 后再 write 目标 → 合并内容
- copy：目标按 create 入暂存（源不动）
每条规则配单测，避免凭直觉合并。

### 3. 工具名→操作归类（含 MCP，可扩展映射表）
`classifyMutationTool(name): { kind, extract(args) } | null`：
- write/write_file/create_file → create-or-modify（path/file_path + content）
- edit/edit_file/str_replace → modify（path + old/new_string 等多形态参数归一）
- delete/delete_file/remove_file → delete
- move/move_file/rename → move（source/destination 或 old/new path）
- copy/copy_file → create 目标
- 未识别的 MCP 工具 → `null`：**不拦截、直走原通道**（无法安全解析未知 schema），审计日志注明。

### 4. 虚拟视图（暂存覆盖）
- `overlayRead(state, path): { found: boolean, content: string|null }`：命中暂存取暂存（delete → not found），未命中回落磁盘由 IO 层执行。
- `overlayEdit(state, path, oldStr, newStr)`：对「有效内容」（暂存或基线）做唯一替换，产出新暂存态；唯一性/未找到错误语义与现 edit 工具一致。
- `overlayGlob(state, diskResults)`：并入暂存 create/move 目标路径，剔除 delete/move 源路径。
- `overlayGrep(state, diskResults, pattern)`：磁盘结果之外，对暂存 create/modify 的内容补扫，产出合成匹配（标注同一文件路径/行号）；delete 的文件剔除。
- `overlayExists(state, path)`：bashGate/验证锁等存在性判定的统一口径。

### 5. 审阅与接受辅助
- `summarize(state)`：按 kind 计数 + 列表（path/kind/字符数/时间）。
- `diffOf(change)`：baseContent vs content 的结构化差异输入（供 DiffEditor）；delete/move 的展示模型。
- `checkConflict(change, currentDiskHash)`：基线哈希比对，不一致即冲突。
- `serialize(state)` / `deserialize(json)`：JSON 安全（Map ↔ 数组），坏数据跳过单条不拖垮。
- `applyPlan(state, paths[])`：纯计算出「接受子集」后的落盘操作序列（mkdir/write/delete/move）与剩余 state；拒绝子集同理。

### 6. 提示词约定（纯文本片段）
`buildStageNotice()`：审阅模式注入系统提示词的说明——改动先入暂存不生效、读改自动走暂存视图、bash 需用户先接受暂存、文件编辑完成即可结束本轮（验证在用户接受后进行）。

## 四、接线点（薄壳，规则不进主循环）

1. **`handlers/staging.ts`（新建，IO + IPC）**
   - 持久化：`<workspace>/.trae/staging/pending.json` 原子写（临时文件 rename）；`loadStage(workspace)`（坏 JSON 容错为空）。
   - 接受落盘：按 applyPlan 执行（mkdir 父目录、writeFile；delete 走既有删除语义；move 跨设备回退 copy+rm），落盘后重写 pending.json；拒绝只重写。
   - IPC 通道：`staging:get`（含摘要）、`staging:diff`（path）、`staging:accept`（paths[] 或 all）、`staging:reject`（paths[] 或 all）、`staging:setEnabled`（开关）；事件 `staging:changed` 推全窗口（同窗口事件桥惯例）。
2. **`scheduler.ts`**
   - runWithTools 入参/ctx 增加审阅模式与当前 StageState（从 staging.ts 惰性加载）；未开启时零行为变化。
   - 工具循环：①权限闸之前插入——`classifyMutationTool(name)` 命中且允许 → 走暂存：基线首次触碰时读磁盘捕获（baseContent/hash）→ 纯函数合并/overlayEdit → 回填「已加入待审阅变更（N 个文件待接受）」结果（推 onToolCall/onToolResult，UI 显「待审阅」态而非「已写入」）→ persist 暂存文件 → continue；不调 callMcpTool。
   - bash 门：preflight（bashGate）之后、①权限闸之前——审阅模式且暂存非空 → 推 bash 接受请求事件并挂起 Promise；接受 → 全部落盘清空、继续执行；拒绝 → 回填原因 continue。
   - 只读工具：read/edit 之外的 grep/glob 在 callMcpTool 结果上做 overlay 纯函数后处理；read 命中暂存直接回填不调工具。
   - 收尾：validateTaskCompletion 的 fileExists 判定走 overlayExists（暂存中即算存在）；任务完成时事件携带 pending 计数。
3. **`aiScheduling.ts`**：makeStagingEvents（staging:changed 订阅/退订）+ makeSend；RunHandle 增 stageEnabled/stagingPath 字段；scheduleChatWithTools 起始把审阅开关随 params 传入。
4. **preload/index.ts + index.d.ts + renderer api.d.ts**：暴露 staging 五通道 + onStagingChanged；新增开关类型（独立于 PermissionMode）。
5. **promptBuilder.ts**：审阅开启时 S 层注入 buildStageNotice；S1 不重构。
6. **taskSnapshot（㊜联动）**：TaskSnapshotFile 增 `stagedChanges: StagedChange[] | null`（schemaVersion 不 bump：旧文件该字段缺失按 null 处理，解析向后兼容）；暂停/中断 persist 时带上；scheduleTaskResume 恢复后重建 StageState。放弃任务路径：回滚后清空暂存文件。
7. **UI（科技蓝青/cp-glass，中文注释）**
   - 新增 `components/StagingPanel.vue`：modal（复用现有 modal 样式）——文件列表 + kind 徽标（新增青/修改蓝/删除红/移动紫）、Monaco DiffEditor 双栏、逐行接受/拒绝、全部接受/全部拒绝、冲突红色阻断、空态；任务进行中实时刷新。
   - ChatPanel：头部加暂存图标 + 待决数角标（点击开面板）；任务完成且有 pending 时消息区显「N 个文件待审阅，接受后生效」提示条 + 「去审阅」按钮；加审阅模式开关。
   - SettingsPanel 通用 Tab：增「变更审阅（改动先暂存、接受后落盘）」开关，文案说明与 bash 门行为。
   - ToolEventCard：暂存态结果显「待审阅」而非成功写入。

## 五、不做什么（显式冻结范围）

1. 不做 bash/终端产生的文件改动的暂存（bash 直触磁盘；以「bash 接受门」保证执行前暂存已清空，命令之后的新改动如需再审由模型后续文件操作自然入暂存）。
2. 不做未映射 MCP 工具的暂存（直走 + 审计）。
3. 不做逐 hunk/逐块接受——仅文件级。
4. 不做多版本暂存历史/分支化暂存——单一 pending 区。
5. 不做暂存区与 git index 的双向同步（接受即普通工作区改动，由用户自行 commit；不代跑 git add）。
6. 不做默认开启、不做强制策略（如公司管理员策略）。
7. 不重构①权限闸、②git.ts、㊜快照主结构；不改 bashGate 规则与工具 schema。
8. 不做暂存变更的云端/多端同步。

## 五-补、默认关闭下的行为矩阵（自检用）

| 场景 | 审阅关（现状，零变化） | 审阅开 |
|------|----------------------|--------|
| write/edit | 权限闸 → 直接落盘 | 硬规则照拦；通过后入暂存，不落盘 |
| read/grep/glob | 直读磁盘 | 暂存覆盖视图 |
| bash | bashGate + 权限闸 → 执行 | 暂存非空先批量接受；之后 bashGate + 权限闸 → 执行 |
| ask 模式文件弹窗 | 逐条问 | 文件类不弹（未生效）；bash 仍问 |
| 暂停/崩溃 | 快照恢复 | 快照 + pending.json 双重携带，恢复后续用 |
| 放弃任务 | checkpoint 回滚 + 清理 | 同左 + 清空暂存 |

## 六、验证方式

1. **单测**：新增 `changeStage.test.ts`，必盖——操作代数全表（含 create+delete 消失、delete+write 复活、move 合并）、归类映射与未识别回落、overlay 四类（读/改/grep/glob，含中文路径与大小写）、冲突检测、序列化坏数据、接受/拒绝子集与剩余态；误报控制（普通文件读写不受影响、未开启模式零变化路径）。预计 40+ 例，计数只增。
2. **三件套**：`npm run typecheck` 双端零错误；`npx vitest run` 全绿（基线 977 只增）；`npx electron-vite build` 通过。
3. **CDP 真窗冒烟**（临时脚本用完即删）：开启审阅 → 跑小任务（新建/修改文件）——断言：任务期间磁盘无新文件、AI read 能读到暂存内容、同文件多次写合并为一条、暂存面板 diff 正确；「全部接受」后文件落盘、pending 清空；另跑「拒绝」场景文件不存在；bash 接受门：暂存非空时 bash 前浮层出现、接受后命令真实执行；重启应用后 pending 仍在；放弃任务后暂存被清空、磁盘由 checkpoint 回滚干净。
4. 文档：更新《项目结构说明.md》（7.1 表 + 7.2 ㊝ 小节 + 五章机制索引 + 目录树）、《日志.md》（头部日期/进度/状态表/P4 记录），数字与 vitest 输出一致。
