# ㊜-1c 中止贯通：超时杀循环、候选串行化 — 实施计划

> P4 第 ㊜ 项第三期。1a（任务快照 + 崩溃恢复）、1b（软暂停/继续/放弃门）已交付；
> 1c 修掉 1b 冒烟期间暴露、并在《日志.md》挂账的遗留风险：**withToolsTimeout 超时只 reject 包装器、不 abort 底层 runWithTools 循环——超时回退候选模型时，老循环成孤儿仍在跑工具，两个循环并发执行副作用**。
> 事故实证：1b 冒烟中孤儿循环自动执行 `npm install vue@2.7.16`，把项目 vue 从 3.5.43 降级（已人工还原）。

## 一、现状与根因

1. `withToolsTimeout(promise, ms)`（scheduler.ts L552）：超时只 `reject(new Error('工具调用整体超时'))`，底层 promise 与 `signal` 毫无关系。
2. 候选 for 循环 catch 到超时立即 `continue` 启动下一候选 → 老循环 + 新循环并发；两者都能过权限闸执行写文件/终端命令。
3. 与 1b 软暂停的两个死锁/错序点：
   - 超时点火时若 gate 正 parked（paused），老循环永不出结果，catch 里若 await 底层会死锁；
   - 超时点火时若 phase=pausing（暂停请求已发、还没到安全点），下一个安全点 `parkIfPausing()` 会照常 pausing→paused 挂起，无视 abort。
4. runWithTools 内 `signal.aborted` 只在轮首处理；工具批次中 break 后会一路走到正常完成收尾（persist('completed')、写成功笔记），abort 语义不完整。
5. provider 侧：OpenAI 兼容/Anthropic 的 in-flight HTTP 可经 `provider.abort()` 掐断；**ollama provider 的 abort 是 no-op**（ollama 库不支持），模型调用只能等自然返回——只读 HTTP 无副作用风险，本期不接（在文档注明"尽力而为、安全点退出"）。

## 二、目标（1c）

1. **超时即中止**：整体超时点火 → 当前候选的 runWithTools 收到 abort，在最近安全点（轮首/工具批次相邻调用间）退出，绝不继续发起新的副作用工具。
2. **候选串行**：catch 到超时/错误后，先 abort、再 `await 老循环 Promise`（吞掉其结局），确认退出后才启动下一候选。代价：错误响应要等"在途单个工具"结束（工具内部不打断是 1b 既定语义），用正确性换及时性，值得。
3. **超时按 interrupted 落快照、用户停止按 aborted**：用 AbortSignal.reason 区分——超时时 attemptAbort.abort(TimeoutError) → persist('interrupted')（全部候选失败时恢复条可续跑，与现行为一致）；外部 signal（停止/放弃）→ persist('aborted')。
4. **暂停冻结超时预算**：gate paused 期间挂表（不计入超时），resume 后用剩余预算重新计时；pausing 不影响。杜绝"暂停中等来超时"。
5. **parkIfPausing abort 感知**：接受可选 AbortSignal——pausing 时若信号已 abort 则不进 paused；paused 期间信号 abort 立即醒来。保证第 1 条在任何 gate 相位都成立。
6. 批次中 break 后若 signal.aborted，走与轮首一致的 abort 收尾（不写 completed/成功笔记）。

## 三、设计与改动清单

### 1. 纯函数/协调层（零 IO，配单测）

**A. `ai/taskControl.ts` 增强**
- 多订阅者：`onChange` 单槽改为 `addChangeListener(cb): () => void`（内部 Set；emit 逐个 try/catch）；scheduler L919 与既有测试迁移。
- `parkIfPausing(abortSignal?: AbortSignal): Promise<ControlPhase>`：
  - phase!=='pausing' → 立即返回（不变）；
  - pausing 且 abortSignal?.aborted → **不转移**、不挂起，直接返回 'pausing'（调用方随后 abort 检查退出）；
  - pausing→paused 后，waiter Promise 与 abort 信号竞赛（`Promise.race` + once 监听，醒来清理监听）；abort 醒来时 gate 相位保持 paused（不 emit），调用方走 abort 路径；
  - 多个安全点并发 park 时，各自挂各自的 abort 监听，信号 abort 全部醒来。

**B. 新增 `ai/pausableTimeout.ts`（零 IO，仅 setTimeout/Date，配单测）**
- `class PausableTimeout`：`start(onFire)`、`cancel()`、`bindGate(gate): () => void`（订阅 paused→disarm 记录剩余、running→用剩余 arm；pausing 不动）；
- 内部仅状态：remaining/deadline/timer，边界 remaining≤0 立即点火；重复 cancel/start 安全。
- scheduler 的 `withToolsTimeout` 改为薄壳：构造 PausableTimeout，有 gate 则 bind，settle 时 cancel+unbind。

### 2. 薄壳接线（scheduler.ts）

- `scheduleChatWithTools` 候选循环每次迭代：
  - `const attemptAbort = new AbortController()`；外部 signal：已 abort 则立刻 abort，并加 `abort` 监听（attemptAbort.abort(signal.reason)），finally 移除；
  - runWithTools 的 signal 参数改传 `attemptAbort.signal`；
  - 先拿 `let runPromise = runWithTools(...)` 再交给 withToolsTimeout（传 gate）；
  - catch：记录 lastError → `attemptAbort.abort(new TimeoutBudgetError())`（出错非超时也幂等 abort）→ `provider.abort?.()` → `try { await runPromise } catch {}` → 再继续下一个候选；
  - 成功路径不变（pruneInterruptedSince 天然清掉本候选 interrupted 快照）。
- `scheduleTaskResume`：同样的 attemptAbort 链接 + catch await（单候选）。
- runWithTools 内：
  - 抽 `finishByAbort()`：tracer finish + 按 `signal.reason` 是否 TimeoutError 决定 persist('interrupted'|'aborted') + 返回「（任务执行超时）/（任务已被用户中止）」；轮首先用；
  - 批次 break 后（for 轮结束处）若 signal.aborted → return finishByAbort()，不再走 drift/笔记/completed 收尾；
  - 两处 `gate?.parkIfPausing()` 改传 `signal`。
- 超时报错文案保留「工具调用整体超时」（PausableTimeout 点火 → reject）。
