# ㉛ 流式工具事件 UI —— 计划文档

## 现状

事件管道已全通，但 UI 消费不足：

- 主进程 `scheduler.ts` 已回调 `onToolCall(name, args)` / `onToolResult(name, result)` / `onModelCall(model, phase)`
- `handlers/aiScheduling.ts` 已 `send('ai:toolCall' / 'ai:toolResult' / 'ai:modelCall')`
- preload 已暴露 `window.api.ai.onToolCall / onToolResult / onModelCall`
- `stores/chat.ts` 已订阅：
  - `onToolCall` → 只更新 `thinkingHint`（如 `read path=xxx`）+ `progress.tool`
  - `onToolResult` → 推一条 `system` notice 消息（`read path=xxx ✓`），todo_write 除外

问题：工具执行过程对用户不可见——不知道 AI 在调什么工具、参数是什么、成功还是失败、耗时多少；notice 消息是纯文本，无法折叠，刷多了会刷屏。

## 目标

把工具调用/结果以**结构化卡片**嵌入消息流，实时展示：

1. 工具名 + 参数摘要（path/command/query 等关键字段）
2. 执行状态：进行中（spinner）→ 成功 ✓ / 失败 ✗
3. 耗时（call 到 result 的差值）
4. 可展开查看完整结果文本（默认折叠，避免刷屏）
5. 科技极客风格、蓝青配色，与应用整体一致

## 设计

### 数据层（`stores/chat.ts`）

新增工具事件类型与状态：

```ts
export interface ToolEventItem {
  id: number               // 自增
  name: string             // 工具名
  args: Record<string, unknown>
  argsBrief: string        // summarizeTool 摘要
  status: 'running' | 'ok' | 'fail'
  startedAt: number        // Date.now()
  durationMs?: number      // result 到达时回填
  result?: string          // 完整结果（折叠展示）
}
```

- `toolEvents = ref<ToolEventItem[]>([])`：当前会话工具事件列表（上限 200 条，防内存膨胀）
- `onToolCall`：`push` 一条 running 事件，更新 `thinkingHint`（保留）
- `onToolResult`：按 name 从尾往前找最近的 running 事件，回填 status/duration/result；不再推 notice 消息（用卡片替代），todo_write 仍静默
- `send / clear / 切换会话` 时清空 `toolEvents`

### 渲染层（`ChatPanel.vue`）

- 消息列表渲染循环中，在 `assistant` 消息之后插入该消息对应的工具卡片（按时间顺序）
  - 简化方案：工具事件独立成区，放在消息流中当前正在流式的 assistant 消息之后；或直接在消息列表渲染时按 `ts` 穿插
  - 最简单且准确：**工具卡片作为 `role: 'tool'` 的消息入 `messages` 数组**，content 存 JSON 序列化的 ToolEventItem；渲染时遇到 `role==='tool'` 用 `<ToolEventCard>` 组件渲染而非 Markdown
  - 这样天然按时间穿插在对话流中，且持久化过滤逻辑已有（`role !== 'tool'` 不入库）
- 新增 `components/ToolEventCard.vue`：
  - 折叠态一行：状态图标（⏳/✓/✗）+ 工具名 + argsBrief + 耗时（`1.2s`）
  - 点击展开：`<pre>` 展示完整 result（等宽字体，最大高度滚动）
  - 失败态红色边框/图标，运行中青蓝色呼吸

### 样式

- 复用 `cp-glass` 玻璃拟态卡片风格
- 边框/图标色：运行中 `--cyber-cyan`、成功 `--cyber-green`、失败 `--cyber-red`

## 不做

- 不改主进程事件结构（已够用）
- 不做工具结果内容的二次 Markdown 渲染（`<pre>` 纯文本即可）
- 不做历史会话的工具事件回放（tool 消息本就不入库）

## 验证

- 单测：无需新增纯函数（UI 层），但 `summarizeTool` 已有则补参数摘要边界用例
- 三件套：双端 typecheck + 全量 vitest run + build
- CDP 真窗冒烟：发一条触发 read/bash 的消息，看卡片实时出现、耗时回填、展开正常
