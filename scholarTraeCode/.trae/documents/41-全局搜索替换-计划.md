# 1.2 全局搜索/替换 实施计划

> 来源：路线图 39 §1.2（P0）。目标：左栏搜索 Tab，ripgrep 引擎，万文件秒级搜索 + 可预览的批量替换。

## 一、现状研究结论

**引擎现状**
- 本机无 `rg`（PATH 无、`resources/bin` 不存在），项目也未装任何 ripgrep 包。
- 现有 AI `grep` 工具在 [builtinTools.ts](file:///d:/47.104.20.186/aiProject/scholarTraeCode/src/main/ai/builtinTools.ts#L191-L233)：纯 Node 递归 `walk` + 逐文件读 UTF-8 + 正则，硬编码 `-i`、glob 只是子串匹配、不尊重 `.gitignore`、默认还跳过全部点目录；万文件场景达不到 2s 验收。
- 另有 `glob` 工具（简易 glob→正则）、`changeStage.overlayGrep`（暂存叠加，独立）。

**左栏结构**
- 左栏 Tab 切换在 [FileTree.vue](file:///d:/47.104.20.186/aiProject/scholarTraeCode/src/renderer/src/components/FileTree.vue#L17)：`leftTab: 'files'|'debug'|'validation'|'problems'`，模板 L634-678；新增一个 `search` 分段即可。
- 跳转机制现成：`ws.openFile(absPath)` + `ws.requestReveal(line, column)`（1-based），ProblemsPanel 同款。

**IPC / 接线约定**
- handler 模块：`ipcMain.handle` + 返回 `{ok, data|error}`，注册函数在 [main/index.ts](file:///d:/47.104.20.186/aiProject/scholarTraeCode/src/main/index.ts#L186-L201) app.whenReady 中统一调用。
- 边界检查复用 `terminal/shellProbe.ts` 的 `isWithinWorkspace`（git.ts 已这样用）。
- preload 按域分块（terminal/git/…），类型在 [api.d.ts](file:///d:/47.104.20.186/aiProject/scholarTraeCode/src/renderer/src/api.d.ts) 同步；i18n 在 `locales/zh-CN.ts` + `en.ts`。
- 打包：electron-builder `asar:true`，二进制须 `asarUnpack` 并在主进程把路径中的 `app.asar` 改写为 `app.asar.unpacked`（标准做法）。

**依赖方案**
- `@vscode/ripgrep@1.18.0`：主包是薄封装（导出 `rgPath`），平台二进制走 optionalDependencies；Win x64 装 `@vscode/ripgrep-win32-x64`（约 5.4MB，内含 rg.exe）。npm registry 可达。
- 用 `rg --json` 输出（事件流：match/context/summary），天然 UTF-8、路径与换行转义安全，比解析人类输出稳。

## 四、关键参数与语义约定

- 选项：`caseSensitive`（默认关 → `-i`）、`wholeWord`（`-w`；替换侧用 `(?<![A-Za-z0-9_])…(?![A-Za-z0-9_])`）、`regexMode`（默认关 → `-F` 字面量；开时原样传 rg，替换侧直接 new RegExp 并校验）。
- glob：include 可多个（每个一个 `-g`），exclude 转 `-g '!…'`；空则不传；分隔符支持逗号/空白切分。
- 通用 rg 参数：`--json`、`--max-columns=512 --max-columns-preview`、默认尊重 .gitignore/.ignore（不搜隐藏文件，rg 默认行为）、`--no-require-git`。
- 上限：结果聚合到 5000 处即终止（停止读流/kill 进程），响应带 `truncated:true`；每文件分组含 matchCount。
- 匹配列：取 submatch.match 在该行 JS 字符串中的实际位置（rg 的 start 是字节偏移，CJK 会偏），高亮在渲染端按正则做，不依赖字节列。
- 替换：替换串支持 `$1`/`$&` 等（regex 模式）；字面量模式原样替换；保留原 EOL 与 BOM；单文件 >5MB 跳过替换并在预览中标注；写回前重读复核匹配数，不一致则跳过该文件并回传 skipped。

## 六、风险与应对

- 打包后 rgPath 落在 app.asar 内：路径改写 app.asar.unpacked + asarUnpack 双包条目。
- optionalDependency 在某些 npm 配置下不安装：安装后显式核验，rgPath 解析失败时 grep 工具走旧回退、搜索面板返回明确错误文案。
- 大仓库输出爆量：5000 截断 + max-columns 限制；spawn 完成后才 resolve，失败（rg 非零退出且无 match 事件）转错误文案。
- 替换误伤：必须预览 → 勾选 → 二次确认；写回前重读复核；与现有 checkpoint（git 检查点）能力互补，不另造快照。
- 网络盘 D: 文件监听不触发重建是既有问题：改源码后手动重启 dev，验证以 out 构建产物 + CDP 为准。

**实施中与原计划的差异（重要演进）**
1. **applyReplace 签名演进**：落盘复核的基准改为 UI 预览时刻的计数。初版在 apply 内部重新生成计划再自比，基准随当前文件变化、复核恒真；现签名为 `applyReplace({…params, selections: [{path, expectedCount}]})`，selections 由渲染端勾选集合携带，主程序落盘前重读 currentCount 必须等于 expectedCount，不等按 `skipped='changed'` 跳过。
2. **响应式 Proxy 跨 contextBridge 会静默挂起**：SearchPanel 通过 props 把载荷传给 ReplacePreviewModal 时，载荷被 Vue 包成 reactive Proxy，浅展开后嵌套的 includes/excludes 数组仍是 Proxy；Electron 序列化挂起（不报错），弹窗永久卡 loading、主进程无日志。修复：modal 内 `plainPayload()` 逐字段重建普通对象、数组用 `Array.from` 脱壳。后续任何「props/store 对象直接作为 IPC 参数」均需照此处理。
3. **hidden 页面 timer 节流**：窗口最小化时 `document.visibilityState==='hidden'`，Chromium 把 `setTimeout` 节流到最小 1 秒（120ms 防抖实测 1008ms）；冒烟中多次「结果异常」实为固定等待时长不足。属环境行为，用户正常使用（窗口可见）不受影响。
4. `@vscode/ripgrep` 为 ESM-only，CJS 主进程无法 require：`resolveRgPath` 靠 fake require.resolve 定位平台包（dev），打包态经 `toUnpackedPath` 改写 asar.unpacked。
