## 二、4.1 大型代码库理解与迭代（s42–s44，P0，6–9 天）

**目标**：万行级多模块仓库迭代时，Agent 不遗忘历史逻辑、不漂移、改动可审。

- **s42 符号级代码索引接线**：在 code-index 既有基础上落地「定义→引用」图谱（ts-morph/regex 双通道，前端 TS 与 Python 优先）；Agent 工具新增 `find_references` / `symbol_outline`，改函数前强制拉取调用方清单注入上下文；索引增量更新（文件保存事件驱动，不全量重建）。
- **s43 spec 锚点与漂移拦截**：开工时从计划文档提取「约束清单」（不可改文件、公共接口签名、既有行为断言）落 `.trae/anchors.json`；每步工具调用后比对锚点（改了禁改文件/删了导出符号即阻断并提示）；与 30 偏差检测合并呈现，长任务中途随时可「对齐检查」。
- **s44 变更集分类审阅**：StagingPanel 在 hunk 清单上叠加分类标记——「需求直接相关 / 顺带改动 / 高风险触碰（核心模块、公共类型）」三档；分类依据 s42 引用图谱 + s43 锚点；可疑改动默认不勾选，需人工显式确认。
- 单测：索引构造/增量更新、锚点比对、分类规则；CDP 冒烟（构造跨文件重构，验证调用方清单注入、锚点阻断、三档标记渲染）。

## 三、4.2 工程交付闭环（s45–s47，P0，7–10 天）

**目标**：生成源码 → 可交付成品，中间环节不再靠人读报错。

- **s45 环境诊断与依赖自修复**：终端非零退出时自动捕获 stderr，分类器判定「缺依赖 / 版本冲突 / 系统差异 / 代码错误」；前三类进入修复循环（装包、锁版本、改镜像源、降级建议），每步修复需用户确认卡片；修复动作全程留痕可回滚（承 ai-git-checkpoint）。
- **s46 测试自动生成与回归**：「为改动补测试」命令——按变更 diff 生成 vitest 用例骨架（纯函数优先），AI 填充断言后人审入库；改动落盘后自动跑「受影响测试子集」（依 s42 引用图谱圈定）再全量；测试失败进入 s45 同款修复循环。
- **s47 一键打包成品**：electron-builder 流水线接入——`package.json` 补 dist 脚本与产物配置（NSIS 安装包 + portable exe），icon/签名占位；打包过程进任务面板可见日志；产物路径与版本号回写构建卡片；跨平台（win/mac/linux）配置预留但仅 Windows 真机验收。
- 单测：错误分类器、修复动作生成、受影响测试圈定；CDP 冒烟（构造缺依赖报错→修复卡片→确认后通过；改一个函数→自动跑子集；dist 产物生成）。

## 四、4.3 Agent 工作流可视化与可控性（s48–s50，P1，6–8 天）

**目标**：执行不黑盒、子任务可单独干预、多 Agent 可并行。

- **s48 执行时间线回溯**：在 31 流式事件之上固化「步骤时间线」视图——每个工具调用/文件修改一条记录（含 AI 自述理由、diff 摘要、耗时、结果状态），支持点击展开与回放定位；失败步骤红色标记并可「从此步重跑」（承 34 快照）。
- **s49 卡片式任务看板**：计划步骤渲染为看板列（待办/进行中/待验收/完成），卡片绑定 s 编号与验收证据；支持单卡片暂停/回滚（承 35）、人工改派优先级；看板状态与 44 式验收总表双向同步。
- **s50 多 Agent 并行编排**：承 subagents-enhance 落地「角色 Agent」——前端/后端/测试三预设，各持独立上下文窗口与工具白名单；编排器按看板卡片分派，冲突文件写前取锁（承 37 事务暂存区）；汇总 Agent 负责冲突裁决与验收合并。
- 单测：时间线记录结构、看板状态机、文件锁互斥；CDP 冒烟（时间线回放、单卡片回滚、双 Agent 并行改不同文件不串扰）。

## 五、4.4 IDE 性能与调试 AI 深化（s51–s53，P2，5–7 天）

- **s51 大项目性能治理**：建立性能基线脚本（启动耗时、大文件打开、索引内存峰值入档）；按需加载改造——Monaco 模型懒建、文件树虚拟化、索引 worker 化；多项目窗口内存隔离核查。
- **s52 调试器 AI 闭环**：在 s41 只读工具之上补写侧——`applyBreakpoint`（AI 建议断点一键落）、异常捕获时自动采集堆栈+变量快照注入修复对话、「继续到修复验证」联动 s46 回归。
- **s53 验证**：性能前后对比入档；CDP 冒烟（AI 建议断点落盘、异常→修复建议→回归通过链路）。
- 插件生态一项本批不立项：优先打磨内置能力，生态兼容（VSCode 插件适配层）待 M5 评估。

## 六、4.5 学术 / 报告链路（s54–s56，P2，5–7 天）

**目标**：实验数据进，规范报告出，一站式不落地到外部工具。

- **s54 数据→图表**：内置图表渲染器（接管实验输出 CSV/JSON），学术规范预设（dpi/字体/配色），图表作为一等附件可插入对话与文档。
- **s55 报告生成**：实验元数据 + 图表 + 结论 → 结构化报告（Markdown 母版，章节模板可配）；一键导出 docx/LaTeX（pandoc 管线或纯 TS 实现，依赖体积权衡后定）。
- **s56 参考文献与验证**：文献条目管理（BibTeX 导入/生成），正文引用标注联动；CDP 冒烟（CSV→图表→报告→导出链路走通）。
- 本项与 scholar 定位直接相关，作为 M4 收尾差异化能力。

## 七、全局风险与约定

| 风险 | 应对 |
|------|------|
| 符号索引对动态语言（Python）召回不全 | 双通道（静态分析 + 运行时采样）并存；召回率入验收记录，不虚报 |
| 锚点误报阻断正常迭代 | 锚点只阻断「禁改清单」，其余降级为警告；清单人工可编辑 |
| 依赖自修复改坏环境 | 每个修复动作前打 checkpoint；修复白名单制（仅装包/锁版本/换源） |
| electron-builder 打包体积与签名 | 首版不签名、只出 NSIS+portable；体积超阈值（300MB）告警不阻断 |
| 多 Agent 上下文成本翻倍 | 角色 Agent 默认关，看板显式开启；并行上限 4 |
| 性能治理无底洞 | 只做基线脚本量化出的前 3 项瓶颈，达标即收 |

- 每项交付仍守三件套与应用内 modal 约束；编号 s42–s56 只对应本计划，不再外溢。
- 各分项不再单建计划文档（本总纲已到步骤粒度）；如执行中发现某项实质超纲，再回到本文档补充并说明。
