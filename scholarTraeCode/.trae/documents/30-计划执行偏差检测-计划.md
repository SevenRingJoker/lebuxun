# ㉚ 计划-执行偏差检测 —— 计划文档

## 现状与缺口

任务收尾时已有两道检查，但只管「关键产物在不在」，不管「计划与实际是否一致」：

- **验证锁**（validation.ts）：manifest 的 fileExists/commandExecuted 硬约束，缺失则禁止宣布完成；
- **收尾警告**（scheduler.ts L1083）：未 npm install / serve 时附加未验证提示。

覆盖不到的偏差：

1. **步骤遗弃**：模型宣布完成时 TodoStore 仍有 pending/in_progress 项（计划中的显式步骤没做完，没有任何检查）；
2. **产物缺失于异常路径**：验证锁只在「模型想收尾」时触发，dedup 放弃（连续 3 轮重复）、break 等路径可绕过，最终输出里却没有明确的缺失清单；
3. **范围蔓延**：模型跑偏创建了计划外文件（如 smoke 实测中模型自说自话跑 npm build/outdated），用户无从分辨哪些是计划内产物。

## 目标

在任务收尾时统一比对「计划承诺 vs 实际产物」，产出结构化偏差报告：

- 追加到最终输出，让用户看到未完成/缺失/计划外清单；
- 事件推给前端（未来可在工具卡片/轨迹 UI 中展示）；
- 纯函数层 + 单测，scheduler 薄壳接线。

## 设计

### 纯函数层：`ai/planDrift.ts`

```ts
interface DriftInput {
  todos: TodoItem[]                    // TodoStore 当前项
  createdFiles: Set<string>            // ctx.createdFiles
  manifest?: ArtifactManifest | null   // ctx.artifactManifest
  plan?: string | null                 // ctx.plan 文本
}
type DriftKind = 'unfinishedTodo' | 'missingArtifact' | 'unexpectedFile'
interface DriftItem {
  kind: DriftKind
  severity: 'block' | 'warn'
  detail: string                       // 人类可读描述
}
interface DriftReport {
  items: DriftItem[]
  hasBlock: boolean                    // 含 block 级偏差（产物缺失）
  hasWarn: boolean
}
function detectPlanDrift(input: DriftInput): DriftReport
function formatDriftReport(report: DriftReport): string
```

三类偏差：

1. **unfinishedTodo（warn）**：`status !== 'completed'` 的 todo，detail = `#id content`；
2. **missingArtifact（block）**：manifest 中 `kind:'fileExists'` 且带 path 的规则，在 createdFiles 中做后缀匹配（复用 validation.ts 同款规则：normPath + endsWith('/'+target)/===target，逻辑内联保持模块零耦合）；
3. **unexpectedFile（warn）**：仅 manifest 存在（项目创建场景）时计算。createdFiles 中满足以下任一即视为计划内，否则为计划外：
   - 命中任一 fileExists path 后缀模式；
   - 路径或末 2/3 段在 plan 文本中出现（normPath 小写、反斜杠转正斜杠后做子串匹配，兼容绝对路径与计划中的相对写法）。
   - manifest 缺省时不评估（非项目创建任务无明确计划范围，避免误报）。

边界：todos 空 + createdFiles 空 → 空报告；任何输入为空/缺省不抛异常。

### 接线：`scheduler.ts`

收尾段（L1082 npm 验证警告附近、return lastContent 之前）：

```ts
const drift = detectPlanDrift({
  todos: todoStore.items,
  createdFiles: ctx.createdFiles,
  manifest: ctx.artifactManifest ?? null,
  plan: ctx.plan ?? null
})
const driftText = formatDriftReport(drift)
if (driftText) lastContent += driftText
events?.onPlanDrift?.(drift)
```

`ToolsEvents` 增加可选回调 `onPlanDrift?: (report: DriftReport) => void`；aiScheduling.ts 已统一 send 桥，按需转发 `ai:planDrift`（本期前端仅事件透出，不做 UI）。

### 不做

- 不新增前端 UI（报告经最终文本呈现；事件为 C 主线可观测产品化预留）；
- 不解析命令级偏差（哪些计划命令没跑——验证锁 commandExecuted 已覆盖关键命令，自由文本解析不可靠）；
- 不改验证锁行为，偏差检测是收尾后的「如实报告」，不再拦截执行。

## 验证

- planDrift.test.ts：三类偏差命中/不命中、severity 聚合、缺省边界、计划文本匹配、绝对/相对/中文路径；
- 三件套：双端 typecheck + 全量 vitest run + build；
- CDP 冒烟：制造「todo 未全完成」收尾，确认报告段落正确出现。
