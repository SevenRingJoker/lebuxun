# ㊜ 任务级持久化与断点续跑 — 实施计划

> P4 第 ㊜ 项（安全感地基）。按 p-item-delivery 流程：本计划经用户批准后才进入实现。
> 本期交付 **1a**：任务快照原子写 + 崩溃/重启/切工作区恢复 + 任务前检查点绑定与一键回滚；
> **1b**（下一项）：运行中暂停/继续、放弃语义细分。
> 另并入 ㉜ 的两个顺手小 UX：偏差明细行点击定位文件、缺失产物一键生成。

## 一、现状与缺口

**已持久化**：会话消息（userData/chat-history，随轮 upsert）、agentTrace（userData/traces，结束时原子写）、agentNotes（`<ws>/.trae/notes/`）、Git checkpoint（trae-checkpoint 提交）。

**任务态全部活在 `runWithTools` 闭包内存中**（证据：[scheduler.ts](file:///d:/47.104.20.186/aiProject/scholarTraeCode/src/main/ai/scheduler.ts)）：

| 内存对象 | 内容 | 可序列化性 |
|----------|------|-----------|
| `convo`（L692，由 messages 拷贝后累积） | 完整工具对话（含注入的验证锁/停滞重启/重规划消息） | AiMessage[] 直接序列化 |
| `ctx: PromptContext`（L643） | createdFiles（Set）、ranNpmInstall/ranServe/ranMkdir、round、stallRestarts、plan、artifactManifest 等 | Set→string[]，其余为原始类型/纯对象 |
| `todoStore: TodoStore` | private seq + items[] | 需补 hydrate 入口 |
| `replanState`（L719） | consecutiveFailures、replanCount、signals[] | 纯对象直接序列化 |
| `executed` Map（L711） | dedup 键 → 首次结果 | Map→entry 数组 |
| stallCount / stallRestarts / dedupStallCount | 循环计数 | number |

循环每轮由 convo + ctx **重建**系统提示词（L740-746），无其他隐藏进程态——这意味着快照恢复在架构上天然可行。

**缺口**：
1. 崩溃/强杀后，文件是否已写、Todo 到哪一步、重规划几次全部丢失，模型只能从头再来（且会重复写文件）。
2. 切工作区/重启后看不到「未完成任务」，没有恢复入口。
3. 任务前检查点虽可自动/手动创建，但与任务无绑定记录，回滚靠用户自己翻 commit。
4. ㉜ 偏差卡片只展示：明细行不能点击，缺失产物不能一键补齐。

## 二、目标（1a）

1. 任务启动即建快照，**每轮收尾原子写** `<workspace>/.trae/tasks/<taskId>.json`；正常完成写 `completed`、中止写 `aborted`、异常写 `interrupted`。
2. 应用启动恢复工作区、或打开/切换工作区后，渲染端可列出可恢复任务（文件里是 `running` 的一律视为崩溃中断 `interrupted`；`paused` 保留——1b 才会产生）。
3. 恢复条（TaskRecoveryBar）展示中断任务摘要（用户请求首行、轮次、产物数、更新时间），提供 **继续 / 放弃并回滚**。
4. 「继续」跳过分类与规划阶段（plan/manifest 已在快照内），从快照轮次重建全部闭包状态进入循环；会话流、工具事件、TODO、偏差卡片全部照常工作。
5. 任务启动时自动创建「任务前」检查点，hash 记入快照；「放弃并回滚」经强确认后走既有 `git:checkpointRestore`。
6. 小 UX：偏差卡片产物类明细行可点击定位（文件存在→打开；不存在→提示一键生成）；缺失产物行内「生成」按钮 → 以定向指令发起一轮补齐任务。

## 三、纯函数设计

### 3.1 新增 `src/main/ai/taskSnapshot.ts`（零 IO / 零 Electron）

```ts
export type TaskStatus = 'running' | 'paused' | 'completed' | 'aborted' | 'interrupted'

/** 快照文件结构（落盘 JSON） */
export interface TaskSnapshotFile {
  schemaVersion: 1
  taskId: string
  workspace: string                 // 归一化绝对路径，恢复时校验
  modelId: string                   // providerId:modelName
  sessionId: string | null
  status: TaskStatus
  userRequest: string               // 末条 user 文本（恢复条摘要用，截断 500 字）
  startRound: number                // 恢复后进入的轮次
  convo: AiMessage[]                // 完整工具对话
  ctx: SerializedPromptContext      // createdFiles: string[]，Set 已转数组
  todoSeq: number
  todos: TodoItem[]
  replan: ReplanState
  executed: Array<[string, string]> // dedup Map entry
  counters: { stallCount: number; stallRestarts: number; dedupStallCount: number }
  preTaskCheckpoint: { hash: string; label: string } | null
  startedAt: number
  updatedAt: number
}

/** 收集器输入：runWithTools 闭包里的活对象 */
export interface SnapshotCollectInput { /* convo/ctx/todoStore/replanState/executed/counters… */ }

/** 序列化：Set→排序数组、Map→entry、数字/布尔原样、缺省字段补默认值 */
export function buildTaskSnapshot(input: SnapshotCollectInput, meta: { status: TaskStatus; updatedAt: number }): TaskSnapshotFile

/** 解析恢复：数组→Set/Map、轮次/计数下限归零、非法/版本不符 → null（调用方跳过并告警） */
export function parseTaskSnapshot(raw: string): TaskSnapshotFile | null

/** 恢复列表分类：running→interrupted（崩溃）、paused→paused、completed/aborted 过滤；按 updatedAt 倒序 */
export function classifyRecoverable(files: TaskSnapshotFile[], now: number): TaskSnapshotFile[]

/** ctx 快照 ↔ PromptContext 互转（createdFiles Set/string[]） */
export function serializeCtx(ctx: PromptContext): SerializedPromptContext
export function restoreCtx(data: SerializedPromptContext): PromptContext
```

边界行为：
- createdFiles/executed 为空 → `[]`，恢复为空 Set/Map；
- convo 缺失/非数组 → parse 返回 null（无法安全恢复）；
- startRound 非法负数 → 归零；超过 MAX_TOOL_ROUNDS → 钳到上限（恢复后立即正常收尾）；
- workspace 与当前打开目录不一致 → 不进入恢复（UI 不展示，由调用方校验）。

## 四、接线点

### 主进程

1. **scheduler.ts `runWithTools`**：
   - 签名新增可选 `taskControl?: { workspace: string; sessionId: string | null; preTaskCheckpoint: {hash;label}|null }`（默认不持久化，保持其他调用方兼容）；
   - 用现有 taskId（L725）；新增闭包内 `persist(status)`：`buildTaskSnapshot` → `saveTaskSnapshot`（IO 失败仅 log.warn，不阻断任务）；
   - 写盘点：每轮工具执行+重规划处理之后（round 末尾）；中止分支（L734-738）；正常/未完成收尾各出口；外层 catch 写 `interrupted`；
   - `runWithTools` 新增可选参数 `restore?: TaskSnapshotFile`：传入时 convo/ctx/todoStore（新增 `TodoStore.hydrate(seq, items)`）/replanState/executed/计数全部由快照恢复，`for` 循环从 `startRound` 起，跳过 L671 自动建清单（ctx 已带清单）。

   - `ai:chatWithTools`：有 workspace 且为 git 仓库时，先 `createCheckpoint(root, '任务前：' + 用户请求前 40 字)`（失败/非仓库静默跳过），hash 经 taskControl 传入；

## 五、不做什么（显式冻结）

- **1b 才做**：运行中「暂停」（轮次/工具间挂起门）、继续暂停态、停止/放弃语义拆分与对应按钮组；本期恢复条的「放弃」只针对已中断任务。
- 不做影子文件系统 / 变更事务 / 逐文件审批（㊝）；计划外文件一键还原随 ㊝ 交付。
- 不做子代理中途续跑：崩溃时若正处于 dispatch_subagents 内，恢复后向 convo 注入一条该工具的错误结果（「子代理执行因中断未完成，请按需重新派发」），由模型自行重试。
- 不做恢复时的隐式模型回退；不合并跨次 trace 文件（同 taskId 两份 trace，可接受）。
- 不做历史任务文件清理/保留策略（只列未完成项，completed/aborted 文件不进 UI；清理策略后续随设置页做）。
- 不改会话消息持久化格式；快照不复制会话内容之外的第二份用户消息（恢复只依赖快照内 convo）。
