# ㊜ 运行中任务暂停 / 继续 / 放弃门（1b）— 实施计划

> P4 第 ㊜ 项的下半期（1a：任务快照 + 崩溃恢复，已交付）。
> 按 p-item-delivery 流程：本计划经用户批准后才进入实现。

## 一、现状与缺口

**1a 已交付**：每轮末快照原子写；崩溃/重启/切工作区后恢复条可「继续 / 放弃（回滚）」；任务前检查点自动创建并绑定。

**当前对"运行中"任务只有一种控制——红色停止键**：
- [ChatPanel.vue](file:///d:/47.104.20.186/aiProject/scholarTraeCode/src/renderer/src/components/ChatPanel.vue) L522 发送中渲染红方块，点击 → `chat.stopSending()` → `ai:stopChat`；
- [aiScheduling.ts](file:///d:/47.104.20.186/aiProject/scholarTraeCode/src/main/handlers/aiScheduling.ts) 持有唯一的 `currentChatAbort: AbortController`，abort 后主循环在轮首（scheduler L892）/工具批次内（L1012）检查点退出，快照落 `aborted`，同时 `provider.abort()` 强行掐断模型 HTTP 请求。

**缺口**：
1. **没有暂停**：用户临时要改主意、下班、切去开会，只能中止任务；重开一轮会重复写文件、重复跑命令。
2. **"停止"是硬中止**：模型请求被立即掐断，正在执行的工具批次中途作废；无法"先收尾再停"。
3. **放弃语义未细分**：运行中放弃无法选择回滚到任务前检查点（要等恢复条——但 aborted 快照不进恢复条）。
4. `paused` 状态在 [taskSnapshot.ts](file:///d:/47.104.20.186/aiProject/scholarTraeCode/src/main/ai/taskSnapshot.ts) 已预留，但全链路没有任何代码会产生它。

## 二、目标（1b）

1. **软暂停**：运行中点「暂停」→ 发出暂停请求（前端立即显示"暂停中…"），主循环**不掐断当前模型/工具调用**，在最近的**安全点**挂起：
   - 安全点 A：每轮模型调用之前（轮首）；
   - 安全点 B：工具批次内、相邻两个工具调用之间。
   - 挂起时落盘 `status:'paused'` 快照，并推送暂停态事件。
2. **进程内继续**：暂停态点「继续」→ 同进程释放挂起，循环原样跑下去（不重载快照、不重新走 IPC 续跑）；若暂停期间应用退出/重启，`paused` 快照天然出现在恢复条，走 1a 既有续跑链路。
3. **运行中放弃**：暂停态（或运行中）点「放弃」→ 行内强确认（复用恢复条同款：默认勾选回滚任务前检查点、无检查点禁用勾选）→ abort 主循环并等待其真正退出 → 可选回滚 → 删除快照。
4. 纯流式聊天（`send`，无工具循环）不产生任务事件，维持现有红方块停止，不出现暂停门。
5. 状态机四相显式建模：`running（运行中）/ pausing（暂停请求已发、等待安全点）/ paused（已挂起）/ aborted（放弃收尾）`，杜绝"else 当运行中"的兜底错误（参考历史经验：前端状态机须覆盖全部状态）。

## 三、纯函数设计

新建 `src/main/ai/taskControl.ts`（零 IO / 零 Electron；Promise 协调非 IO，与纯函数同放一处）。

### 3.1 状态转移（数据驱动表）

```ts
/** 运行门相位（内存内实时态；盘上 TaskStatus 是另一维度） */
export type ControlPhase = 'running' | 'pausing' | 'paused'
export type ControlAction = 'requestPause' | 'reachSafePoint' | 'resume' | 'abort'

export function nextControlPhase(phase: ControlPhase, action: ControlAction): ControlPhase
```

| 当前相位 | 动作 | 下一相位 | 说明 |
|---|---|---|---|
| running | requestPause | **pausing** | 仅登记请求，调用继续执行 |
| pausing | reachSafePoint | **paused** | 到达安全点，真正挂起 |
| pausing | resume | **running** | 安全点前反悔 = 取消暂停请求 |
| paused | resume | **running** | 释放挂起 |
| paused | reachSafePoint | paused | 幂等 |
| 任意 | abort | **running** | 释放挂起；aborted 收尾由 abort 路径负责 |
| 其余组合 | — | 原相位 | 非法/无意义动作静默不动 |

### 3.2 运行门

```ts
export class TaskControlGate {
  getPhase(): ControlPhase
  requestPause(): boolean              // running → pausing，返回是否发生转移
  resume(): boolean                    // pausing/paused → running
  abort(): void                        // 任意 → running 并释放全部等待
  /** 安全点：pausing 时切 paused 并挂起直到 resume/abort；非 pausing 立即返回当前相位 */
  parkIfPausing(): Promise<ControlPhase>
  /** 相位变化监听：scheduler 在此 persist + 推事件（paused → persist('paused')；running → 事件） */
  onChange: ((phase: ControlPhase, prev: ControlPhase) => void) | null
}
```

挂起实现：内部 waiters 数组 + `new Promise<void>(r => waiters.push(r)`；`resume/abort` 排空 waiters。`abort` 后 parkIfPausing 返回 `running`，由调用方随后的 `signal?.aborted` 检查进入既有中止路径。

## 四、接线点

### 4.1 scheduler.ts
- `runWithTools` 新增参数 `gate?: TaskControlGate`（`scheduleChatWithTools` / `scheduleTaskResume` 同步透传，均为可选参数放末尾）。
- 任务启动后（taskId 生成处，L822 附近）：`events?.onTaskControl?.({ taskId, phase:'started', preTaskCheckpoint: taskControl?.preTaskCheckpoint ?? null })`。
- **轮首安全点**（L892 abort 检查附近）：
  ```ts
  await gate?.parkIfPausing()
  if (signal?.aborted) { /* 既有中止路径，persist('aborted') */ }
  ```
  （park 前先有一次 abort 检查，park 返回后再查一次，覆盖"挂起期间被放弃"。）
- **工具批次安全点**（L1010 for 循环内、现有 abort break 处）：循环体开头 `await gate?.parkIfPausing()`，随后仍走 `if (signal?.aborted) break`。
- gate.onChange：转 `paused` 时 `persist('paused')` + 推 onTaskControl('paused')；转 `running`（resume）时推 onTaskControl('running')。persist 失败仍只 warn。
- `ToolsEvents` 新增：`onTaskControl?: (p: { taskId: string; phase: 'started'|'pausing'|'paused'|'running'; preTaskCheckpoint?: SnapshotCheckpoint | null }) => void`。

## 五、不做什么（范围冻结）

1. 不在工具调用**内部**挂起（bash 执行到一半、模型 HTTP 请求途中只登记请求，等其结束）；子代理 dispatch 整体 await 期间不挂起——暂停在 dispatch 返回后的下一个安全点生效（与 1a"子代理中途不续跑"一致）。
2. 不做暂停超时自动放弃、暂停时长统计。
3. 不做多个并发任务的多路控制（架构仍是单 currentRun）。
4. 不改会话持久化格式、不清理 aborted 历史快照。
5. 纯流式（chatStream）不加暂停门。
